# AGENTS.md

Guide for AI agents and newcomers working on the Arffornia Keycloak theme.

## Purpose

Keycloakify login theme for the **infra** Keycloak realm (ArgoCD, Vault, Longhorn, Adminer). Not player
login. The output is a JAR copied into Keycloak `/providers` by a busybox initContainer image.

## Repo map

| Path | What |
|---|---|
| `src/login/KcPage.tsx` | Routes each Keycloak page id to a component |
| `src/login/pages/` | Page components (login, register, error, OTP, ...) |
| `src/login/components/` | Template and shared components (`ui/` = shadcn) |
| `src/login/i18n.ts` | EN/FR message overrides |
| `src/kc.gen.tsx`, `src/main*.tsx` | Generated by Keycloakify |
| `public/keycloak-theme/` | Generated by Keycloakify, ignored by ESLint |
| `vite.config.ts` | Keycloakify plugin config |
| `Dockerfile` | busybox image with the JAR |
| `.github/workflows/` | CI, publish, Trivy |

## Commands

```bash
make install   # npm ci --legacy-peer-deps
make check     # lint + tsc + vite build (what CI runs)
make theme     # JAR in dist_keycloak/ (needs Maven + Java)
npm run dev    # dev server with mock context
```

## Conventions

- English for code, comments, docs, commits, issues and PRs.
- User-visible text goes through `src/login/i18n.ts` with at least `en` and `fr`.
- Conventional Commits; one PR per issue with `Closes #n`.
- Keep generated files (`kc.gen.tsx`, `public/keycloak-theme/`) untouched; regenerate instead.

## Hard rules

- No secrets in the repo.
- Never merge, tag, or push to `main`.
- The theme name is referenced by infra (`login_theme` in `infra/terraform/main.tf`): renaming it must ship
  with the infra change (decision in #18).

## Testing strategy

- Today: lint, type-check and build in CI.
- Planned (#22): Storybook stories for login, register and error pages, and a Playwright smoke test
  against `keycloakify start-keycloak`.

## Gotchas

- `npm ci` needs `--legacy-peer-deps`.
- The postinstall (`keycloakify sync-extensions`) rewrites `package.json` (`lucide-react` range) and
  undoes Dependabot bumps. Do not commit that diff (#19).
- Building the JAR needs Maven; behind a proxy Maven needs its own `settings.xml`.
- The publish workflow pushes `latest` on every main push and infra uses `latest` (#20).
